# 問題データ作成（make-cards）

この暗記アプリ（`暗記アプリ仕様書_v3.md` 2章・7章）の CSV インポート形式で問題データを作る。
出力は `cards/` に置く CSV ファイルで、アプリの「CSVインポート」でそのまま取り込める。

## 1. 依頼を読み取る

依頼から次を読み取る。書かれていないものは既定値を使い、**質問で止めずに作る**
（テーマも元の文章も無いときだけ、何について作るかを聞く）。

| 項目 | 読み取り方 | 既定値 |
|---|---|---|
| 題材 | テーマ（「〇〇に関する」）、貼り付けられた文章、指定されたファイル | なし（必須） |
| 問題数 | 「〇問」「〇枚」 | 10問 |
| 形式 | 「1問1答で」「選択式で」「並べ替えも入れて」など | 題材に合う形式を混ぜる（下記） |
| 難易度・対象 | 「小学生向け」「資格試験レベル」など | 一般的な学習者 |
| 出力先 | ファイル名の指定 | `cards/<題材を表す英小文字とハイフン>.csv` |

形式の呼び方の対応：

| type | 呼び方の例 |
|---|---|
| `single` | 1問1答、一問一答、記述、フラッシュカード |
| `choice` | 多肢選択、選択式、4択、クイズ |
| `matching` | 組み合わせ、対応、マッチング、ペア |
| `ordering` | 順番当て、並び順、年代順、手順 |
| `anagram` | 並べ替え、アナグラム、文字並べ替え |

形式の指定が無いときは、題材に合うものを選んで混ぜる。目安は single と choice を中心に、
年代・手順のように順序がある題材には ordering、用語と意味のような対があれば matching を少し加える。
anagram は単語や短い語句の暗記に向く題材のときだけ使う。

**題材が文章の場合**は、その文章に書かれている事実だけから問題を作る。文章に無い知識を足さない。
文章から作れる数が指定数に届かないときは、無理に水増しせず、作れた数とその理由を報告する。

## 2. 形式ごとの書き方

列は次の順で、ヘッダ行を必ず付ける。`id` は空欄にする（インポート時にアプリが採番する）。

```
id,type,question,choice1,choice2,choice3,choice4,choice5,choice6,answerIndex,answer,explanation
```

| type | choice1〜6 | answerIndex | answer | 守ること |
|---|---|---|---|---|
| `single` | 空 | 空 | 解答（必須） | 解答は短く一意に決まるもの。自己採点なので、言い換えが多い問いは避ける |
| `choice` | 選択肢2〜6件（4件が基本） | 正解の番号（**1起点**） | 空 | 誤答は紛らわしいが明確に誤りのもの。「すべて正しい」系は使わない |
| `matching` | `左:右` を2〜6件 | 空 | 空 | 左も右も重複させない。値に `:` や `\` があればエスケープ（下記） |
| `ordering` | 2〜6件を**正解の順**に | 空 | 空 | 順序が一意に決まるものだけ。問題文に何の順か（古い順、手順順など）を書く |
| `anagram` | 空、または `choice1` にカンマ区切りのトークン1件 | 空 | 完成形（必須） | 拗音・長音などを1かたまりにしたいときだけトークンを使う。トークンを連結すると answer と一致させる |

- 表示時は選択肢の順がシャッフルされるので、`choice` の正解位置を散らす必要はない。
- `explanation`（解説）は全問に1〜2文で書く。答えの根拠や覚え方のヒントにする。
- 問題文・解答・解説は、依頼に別の言語の指定が無ければ日本語で書く。
- 回答状況の列（`checked`〜`suspendedUntil`）は出力しない。

### matching のエスケープ（仕様2.2）

`左:右` はエスケープされていない最初の `:` で区切る。値の中の文字は次のように書く。

- `\` → `\\`（先に置換する）
- `:` → `\:`

例：`開始時刻\:12\:30:Start Time`（左＝`開始時刻:12:30`）、`C\\Users:ユーザーフォルダ`（左＝`C\Users`）

### CSV のクォート（RFC4180）

- カンマ・ダブルクォート・改行を含む値は `"` で囲み、値の中の `"` は `""` にする。
- anagram のトークン（`"ファ,イ,ル"`）はカンマを含むので必ず囲む。
- 文字コードは UTF-8（BOM無し）、改行は LF でよい（アプリはどちらも受け付ける）。

### 例

```csv
id,type,question,choice1,choice2,choice3,choice4,choice5,choice6,answerIndex,answer,explanation
,single,日本の初代内閣総理大臣は？,,,,,,,,伊藤博文,1885年に初代内閣総理大臣に就任した。
,choice,日本の最高峰は？,富士山,北岳,奥穂高岳,槍ヶ岳,,,1,,標高3776m。2位は北岳（3193m）。
,matching,国と首都を対応させよ,日本:東京,フランス:パリ,ドイツ:ベルリン,イタリア:ローマ,,,,,ヨーロッパ主要国の首都。
,ordering,日本の時代を古い順に並べよ,鎌倉時代,室町時代,江戸時代,明治時代,,,,,鎌倉（1185年頃〜）→室町→江戸→明治。
,anagram,「ファイル」を並べ替えよ,"ファ,イ,ル",,,,,,,ファイル,拗音はトークンで1かたまりにする。
```

## 3. 内容の確かさ

- 事実として正しいことだけを問題にする。自信の持てない数値・年号・固有名詞は使わない。
- 時期によって変わる事実（統計値、最新の記録、制度など）は、問題文に基準時点を書くか避ける。
- 1問で問うことは1つにする。問題文だけで答えが一意に決まるようにする。
- 同じ事実を別の問題で繰り返し問わない。問題文の重複もしない。

## 4. 検証して保存する

1. CSV を `cards/<名前>.csv` に書く（`cards/` が無ければ作る）。
2. アプリのインポートと同じ検証を通す：

   ```bash
   node tools/validate-cards.js cards/<名前>.csv
   ```

3. `エラー` が出たら直して再実行する。`警告` も原則直す（重複した選択肢・問題文など）。
4. OK になったら、ファイルの場所・問題数と形式の内訳・題材から作れなかったことがあればその旨を、
   短く報告する。CSV の全文は、依頼者が求めたとき、または10問以下のときだけ会話にも載せる。

取り込み方：アプリのホーム → CSVインポート → ファイルを選択。
